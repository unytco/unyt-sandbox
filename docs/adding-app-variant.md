# Adding a new app variant

This repo builds multiple Tauri app variants (e.g. **unyt-sandbox**, **holo-hosting**) from one codebase. Each variant has its own product name, bundle identifier, icons, and release artifacts. This doc describes what to add when introducing a new variant.

## Overview

- **Single codebase:** One `src-tauri/`; identity and assets are chosen at build time via env and scripts.
- **CI:** Variants are defined once in [`.github/app-variants.yaml`](../.github/app-variants.yaml) (YAML so you can add comments). The workflow reads this file for the build matrix and for the release notes table (identifier = network seed). Set `enabled: false` on an entry to exclude it from builds and from the changelog.
- **Local:** [Makefile](../Makefile) has per-variant targets for prep and build.

---

## 1. Add the variant (CI single source of truth)

Edit [`.github/app-variants.yaml`](../.github/app-variants.yaml). Add a new entry with the same shape as the existing ones (comments are allowed):

```yaml
- id: my-new-app
  product_name: My New App
  identifier: co.example.mynewapp.sandbox
```

**Fields:**

| Field           | Meaning                                                                 | Example                    |
|----------------|-------------------------------------------------------------------------|----------------------------|
| `id`           | Short slug; used for `TAURI_APP_VARIANT`, icon dir name, artifact names, and Linux .deb icon/binary name | `my-new-app`               |
| `product_name` | Display name (window title, about dialog, release assets)              | `My New App`               |
| `identifier`   | Bundle / app identifier (network seed); must be unique per variant       | `co.example.mynewapp.sandbox` |

**Optional:** Set `enabled: false` on an entry to exclude it from the build matrix and from the release notes table (no need to edit the workflow).

The workflow reads this file for the desktop and Android build matrix and for the “Unyt network release” table in the release body. No other workflow edits are required.

---

## 2. Add icons for the variant (optional: use default)

Icons live under **one folder per variant:** `src-tauri/icons/<id>/`. If a variant has no folder, the script falls back to **`src-tauri/icons/default/`** (if it exists).

**To use the default for a variant:** Ensure `src-tauri/icons/default/` exists with a full icon set (e.g. copy from an existing variant: `rsync -a src-tauri/icons/unyt-sandbox/ src-tauri/icons/default/`). Then any variant without its own folder will use default.

**To add variant-specific icons:**

1. **Create the directory** (same structure as existing variants):
   ```bash
   mkdir -p src-tauri/icons/my-new-app
   ```
2. **Copy the full icon set** from an existing variant (or from `default/`), then replace with your assets:
   ```bash
   rsync -a src-tauri/icons/unyt-sandbox/ src-tauri/icons/my-new-app/
   # Then replace PNGs, .icns, .ico, android/, ios/ with your branding.
   ```
3. **Required contents** (same as [tauri.conf.json](../src-tauri/tauri.conf.json) `bundle.icon` and Android/iOS):
   - Root: `32x32.png`, `128x128.png`, `128x128@2x.png`, `icon.icns`, `icon.ico`, `icon.png`, `Square*.png`, `StoreLogo.png` (as used by the template).
   - `android/` – mipmap dirs and launcher assets.
   - `ios/` – AppIcon assets.

Only **variant subdirs** and **`icons/default/`** are committed. The root-level files under `icons/` are generated by the copy script and are in [`.gitignore`](../.gitignore).

## 3. Add Makefile targets (local build)

Edit the root [Makefile](../Makefile).

**Prep target** – generates `tauri.conf.json` and copies icons for this variant (same env as CI):

```makefile
prep-app-my-new-app: install
	TAURI_PRODUCT_NAME="My New App" TAURI_APP_IDENTIFIER=co.example.mynewapp.sandbox TAURI_APP_ID_PREFIX=my-new-app TAURI_DEEP_LINK_SCHEME=my-new-app TAURI_SPLASHSCREEN_TITLE="My New App Loading" TAURI_APP_VARIANT=my-new-app bash scripts/generate-tauri-config.sh
	TAURI_APP_VARIANT=my-new-app bash scripts/copy-app-icons.sh
```

**Build target (desktop)** – prep then Tauri build with the same identity env:

```makefile
build-my-new-app: prep-app-my-new-app
	TAURI_APP_IDENTIFIER=co.example.mynewapp.sandbox TAURI_APP_ID_PREFIX=my-new-app yarn tauri build
```

**Build target (Android, CI-like)** – one command that does prep → regenerate Android project → cleartext script → release build (requires nix and `.#androidDev`):

```makefile
build-android-my-new-app: prep-app-my-new-app
	rm -rf src-tauri/gen/android
	nix develop --accept-flake-config .#androidDev --command bash -c "yarn tauri android init"
	bash scripts/android-uses-cleartext-traffic.sh
	HOLOCHAIN_ARC_FACTOR=0 TAURI_APP_IDENTIFIER=co.example.mynewapp.sandbox TAURI_APP_ID_PREFIX=my-new-app nix develop --accept-flake-config .#androidDev --command bash -c "make build-android-release"
```

Use the same `TAURI_*` values as in the workflow (`id` → `TAURI_APP_ID_PREFIX` / `TAURI_DEEP_LINK_SCHEME`, etc.).

## 4. Optional: per-variant config

- **Updater / deep-link:** If this variant needs different updater endpoints or deep-link schemes, they can be set in [`src-tauri/tauri.conf.template.json`](../src-tauri/tauri.conf.template.json) using the same placeholders (`{{IDENTIFIER}}`, `{{DEEP_LINK_SCHEME}}`, etc.). The generator script already substitutes per-variant env.
- **Rust identity:** [`src-tauri/build.rs`](../src-tauri/build.rs) reads `TAURI_APP_IDENTIFIER` and `TAURI_APP_ID_PREFIX` from the environment; CI and the Makefile set these for each variant, so no code change is needed when adding a variant.
- **Linux .deb icon name:** `mainBinaryName` in `tauri.conf.json` is set from `TAURI_APP_VARIANT` (i.e. the variant `id`). This makes the Linux binary name and the installed icon filename (e.g. `/usr/share/icons/hicolor/128x128/apps/<id>.png`) unique per variant, so both unyt-sandbox and holo-hosting .deb packages can be installed on the same system without file conflicts.

---

## Checklist

- [ ] Add entry to [`.github/app-variants.yaml`](../.github/app-variants.yaml) (`id`, `product_name`, `identifier`).
- [ ] (Optional) Create `src-tauri/icons/<id>/` and add full icon set, or rely on `icons/default/` if present.
- [ ] Add `prep-app-<id>`, `build-<id>`, and (if needed) `build-android-<id>` targets to the root [Makefile](../Makefile).
- [ ] (Optional) Adjust [tauri.conf.template.json](../src-tauri/tauri.conf.template.json) or scripts if this variant needs different updater/deep-link behaviour.

After that, CI will build desktop and Android for the new variant on the next release tag, and you can run `make build-my-new-app` locally.
